# Firmware/Backend Protocol

## Audio Format

The firmware sends raw audio with this format:

- 16 kHz
- 16-bit signed little-endian PCM
- mono
- no WAV header

The initial firmware records up to 4 seconds per push-to-talk turn.

## `POST /api/turn`

Request:

```http
POST /api/turn
Content-Type: application/octet-stream

<raw pcm bytes>
```

Response:

```json
{
  "transcript": "사용자가 말한 내용",
  "answer": "AI 답변",
  "audio_url": "/audio/abcd1234.wav"
}
```

`audio_url` can be `null` when TTS is not configured. In that case the ESP32 prints the reply to Serial.

## `GET /audio/{filename}`

Returns a WAV file generated by Piper. The current firmware skips the 44-byte WAV header and streams the remaining PCM payload to the I2S speaker.

## `GET /health`

Returns:

```json
{"status":"ok"}
```

Use this endpoint to confirm LAN connectivity before debugging audio.

## Why HTTP First

HTTP request-response is intentionally used for the first milestone. It is slower than streaming, but easier to debug with Serial logs, `curl`, and saved PCM files. After the base loop is stable, the next version should move to WebSocket streaming with voice activity detection.
